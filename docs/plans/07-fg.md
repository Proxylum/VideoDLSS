# План этапа 7 — Frame Generation

Дата: 2026-09-19. Ветка: `stage/07-fg`. Требования: ТЗ §4 (стадия FG: цвет + depth + MV → 2×–4× кадров; «Streamline
DLSS-G, скрытый swapchain, readback»; «FG изолирован в отдельный процесс-воркер»), §8 (этап 7: `fg_worker` со Streamline,
скрытый swapchain, readback, IPC; `color_fg` с удвоенным числом кадров; сравнение с RIFE как baseline), §9 («FG даёт ×2
кадров; падение `fg_worker` не роняет GUI»), риски §10 («DLSS-G нельзя запустить offscreen без реального swapchain —
скрытое окно + readback; если не работает — RIFE/FILM как встроенный fallback»).

## Разведка (2026-09-19)

| Что | Статус | Решение |
|---|---|---|
| Streamline (`<SDK>\Streamline`) | только исходники с GitHub: `include/`, `docs/`, сборка через `setup.bat`/`build.bat` (premake, packman); **бинарников `sl.*.dll` нет**; DLSS-G в Streamline работает исключительно через перехват `IDXGISwapChain::Present` | **не используем** — см. следующую строку |
| DLSS SDK 310.9.1 (`<SDK>\DLSS`) | содержит **прямой NGX-API Frame Generation**: `NVSDK_NGX_Feature_FrameGeneration = 11`, `nvsdk_ngx_defs_dlssg.h` / `nvsdk_ngx_helpers_dlssg_d3d.h` / `nvsdk_ngx_params_dlssg.h` (`NGX_D3D12_CREATE_DLSSG`, `NGX_D3D12_EVALUATE_DLSSG`), «DLSS-FG Programming Guide.pdf» (128 стр., v310.7): входы `Backbuffer` (текущий кадр, display-ready), `Depth`, `MVecs` (пиксели в разрешении MV, «от текущего к предыдущему», как у DLSS SR), опционально `HUDLess`/`UI`; выход `OutputInterpolated` (кадр **между предыдущим и текущим** backbuffer, тот же размер/формат); multi-frame: `MultiFrameCountMax` в capability-блоке, `multiFrameCount`/`multiFrameIndex` — evaluate вызывается `count` раз на пару; `Reset` → следующий интерполированный кадр = копия входа; состояния ресурсов как у SR (входы `NON_PIXEL_SHADER_RESOURCE`, выход UAV); `nvngx_dlssg.dll` есть в SDK (`lib/Windows_x86_64/rel`) и в драйвере | **DLSS-G через NGX напрямую, без swapchain и без Streamline** — те же `gpu/Ngx`, `bin/nvidia/`, диагностика, что у SR/NR. Хак «скрытый swapchain + readback» из ТЗ не нужен: NVIDIA задокументировала offscreen-путь. Отклонение от буквы ТЗ фиксируется здесь и в `docs/architecture.md` |
| Камера для DLSS-G | параметры `cameraViewToClip`, `clipToCameraView`, `clipToPrevClip`, `prevClipToClip`, позиция/оси, near/far/FOV — у видео их нет | синтетические константы (как у DLSS5-Feeder для игр без DLSS): перспектива FOV 60°, near 0.1 / far 1000, `clipToPrevClip = prevClipToClip = I` (камера «неподвижна», всё движение — в MV), `cameraMotionIncluded = 1`, `depthInverted = 1` (`depth_dlss`), `mvecScale = (1, 1)` (пиксели), `menuDetectionEnabled = 0`, `motionVectorsInvalidValue = FLT_MAX` — **HACK**, описывается в architecture.md |
| Формат backbuffer | руководство: display-ready SDR/HDR10; примеры `R10G10B10A2_UNORM`, `R8G8B8A8_UNORM`; «3+ канала FLOAT/UNORM/SNORM» | по умолчанию `R16G16B16A16_FLOAT` (наш конвейер) c `ColorBuffersHDR = 0`; при `FAIL_UnsupportedFormat` — автоматический переход на `R8G8B8A8_UNORM` через compute-конверсию (`--backbuffer-format rgba16f|rgba8`) |
| Изоляция процесса | ТЗ требовало воркер из-за перехвата swapchain Streamline; с прямым NGX перехвата нет | «воркером» служит процесс `dlssvid fg`, который запускает GUI через `TaskQueue` (как все стадии): его падение — `taskFinished(false)` + следующая задача (тест с реальным падением процесса через скрытый флаг `--crash-after`). Отдельный exe `fg_worker` и IPC не нужны; папка `fg_worker/` остаётся с объяснением |

| Наивный baseline | — | `blend`: линейное смешивание соседних кадров (CPU, детерминирован, WARP) — точка отсчёта для метрик и тесты стадии без GPU |
| Оценка качества | у FG есть **ground truth**: прореженный вдвое клип → ×2 → сгенерированные кадры сравниваются с выброшенными оригиналами | `dlssvid compare --start 1 --step 2` (новые опции) по `color_fg` против исходного клипа; методика и результаты dlssg / rife / blend в `docs/benchmarks.md` |

## Что делаем

1. **`core/ml/TrtEngine`**: `Options::shapes` (имя входа → фиксированные размеры) → профиль оптимизации для динамических
   ONNX; формы входят в ключ кэша; при загрузке движка формы входов задаются контексту, формы выходов берутся из контекста.
2. **`models/registry.json`**: `rife49` (primary baseline), `rife48`, `rife47` — stage `fg`, прямые URL HuggingFace, лицензия
   RIFE MIT (экспорт — yuvraj108c/ComfyUI-Rife-Tensorrt), параметры `inputs`, `output`, `multiple = 32`.
3. **`core/stages/fg/`**
   - `IFrameGenerator` — `Init(device, FgConfig{width, height, guide size, multiplier 2..4, backbufferFormat, dllDir, model, fp16})`,
     `Generate(FgInputs{prev/cur: текстуры RGBA16F + CPU-копии, depth/mv (+ размеры), reset, frameIndex}, std::vector<PassImage>& out)`
     — бэкенд сам исполняет свою работу (D3D12 / TensorRT / CPU) и отдаёт `multiplier − 1` кадров CPU-изображениями;
     фабрика `dlssg | rife | blend`, `FgAvailable()`, `FgDiagnostics` (GPU, драйвер, DLL + SHA-256, `FrameGeneration.Available`,
     `MultiFrameCountMax`, результат `CreateFeature(FrameGeneration)`, подсказка), индексация кадров (чистые функции:
     real `i·mult`, interp `i·mult + k`, всего `(N−1)·mult + 1`).
   - `DlssgFrameGenerator` — NGX Feature 11 по руководству: capability check (`FrameGeneration.Available`, версия драйвера),
     `NGX_D3D12_CREATE_DLSSG` (`Width/Height` = цвет, `RenderWidth/Height` = guides, формат backbuffer), evaluate `count` раз
     с `multiFrameIndex`, синтетические константы камеры, fallback-guides (константная глубина / нулевые MV с
     предупреждением), readback каждого выхода; лог как у NR (архитектура, DLL, SHA-256, результат создания).
   - `RifeFrameGenerator` — реестр → ONNX → `TrtEngine` (fp16) для паддингованного размера; NCHW RGB [0,1], `timestep`,
     обрезка выхода.
   - `BlendFrameGenerator` — `lerp(prev, cur, k/mult)` на CPU.
   - `FgStage` — цвет из `--color-dir` (по умолчанию `<passes>/color_nr`, иначе `<passes>/color_sr`, иначе видео), guides
     из папок/слота; хранит предыдущий кадр; пишет `color_fg`: реальный кадр `i` → индекс `i·mult`, сгенерированные —
     между ними; манифест `fps × mult`, `frameCount = (N−1)·mult + 1`; превью `--video` с частотой `fps × mult`;
     недоступный бэкенд — инструкция (CLI, код 1) / отключение стадии (пайплайн); скрытый `--crash-after N` для теста изоляции.
4. **CLI**: `dlssvid fg -i in.mp4 -o passes [--backend dlssg|rife|blend] [--multiplier 2|3|4] [--color-dir] [--depth-dir]
   [--mv-dir] [--model rife49|rife48|rife47] [--fp32] [--backbuffer-format rgba16f|rgba8] [--format] [--video --codec]
   [--frames] [--warp] [--dll-dir] [--check] [--json]`; `dlssvid compare --start N --step K`.
5. **GUI/проект**: стадия `fg` в `Project::DefaultStages()` (`dlssg`, ×2); `color_fg` во вьюпорте как пасс (кадры
   отображаются по индексу; воспроизведение с удвоенным fps во вьюпорте — этап 8, ТЗ §6); `fg_worker/README.md` → решение.
6. **Тесты**: юнит — индексация кадров, `blend` (веса, ×3), матрицы камеры (перспектива × обратная = I), формат backbuffer,
   `FgAvailable` сообщения, `TrtEngine` с профилем (SKIP без TensorRT / модели); интеграционные — `FgStage` со `blend`
   на WARP (2N−1 кадров, fps ×2, манифест, превью, вход из `color_nr`, ×3), `dlssg` без GPU (инструкция / отключение),
   `dlssg` ×2 и ×3 на NVIDIA GPU (SKIP без DLL), `rife` на GPU (SKIP без TensorRT/модели), CLI `fg`, `fg --check`,
   `--crash-after` (процесс падает, вызывающий жив); app — `TaskQueue` с реально упавшим процессом `dlssvid fg --crash-after 0`.
7. **Документация**: `docs/architecture.md` (стадия 7, решение «NGX вместо Streamline», HACK-строки: синтетическая камера,
   readback, паддинг RIFE, blend), `docs/dll-setup.md` (`nvngx_dlssg.dll`, `fg --check`), `docs/benchmarks.md` (методика
   ground truth и результаты dlssg / rife / blend), README, `fg_worker/README.md`, `Memory/*`.

## Открытые вопросы
- Примет ли DLSS-G `R16G16B16A16_FLOAT` как backbuffer SDR (0..1, sRGB) — иначе `rgba8`; проверяется на машине.
- Достаточно ли синтетической камеры: модель использует depth + MV + матрицы для реконструкции; при артефактах —
  вариант «только MV» (`clipToPrevClip = I` уже означает это) и сравнение с RIFE по ground truth.
- `MultiFrameCountMax` на Ada (MFG официально — RTX 50): ×3/×4 могут быть недоступны — тогда ×2 через DLSS-G и ×3/×4
  через RIFE (`timestep`).

## Отложено / вне этапа
- Воспроизведение `color_fg` во вьюпорте с удвоенным fps (ТЗ §6) и объединение с аудио — этап 8 (`process`, финальный мукс);
  UI/HUDLess-слои (для видео нет UI); FILM как второй fallback.

## Приёмка (ТЗ §8–9)
- `dlssvid fg --backend dlssg` даёт `color_fg` с ×2 (и ×3/×4, если `MultiFrameCountMax` позволяет) на RTX 40; `rife` и `blend` —
  baseline; падение процесса `dlssvid fg` не роняет GUI (`TaskQueue`) и CLI; ground-truth сравнение в `docs/benchmarks.md`;
  решение и хаки — в `docs/architecture.md`; PR.
