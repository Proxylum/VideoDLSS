# UX-принципы и чек-лист ревью интерфейса `dlssvid-gui`

Короткий документ по мотивам методики Impeccable, переложенной на Qt 6 Widgets: сначала контекст продукта, потом
принципы, потом чек-лист, по которому проходит любое изменение интерфейса (TASK-0012, `Output/ux-audit/`).

## Контекст продукта

- **Что это.** Офлайновый пайплайн улучшения видео на технологиях DLSS: глубина и векторы движения → апскейл (DLSS SR) →
  Neural Rendering → генерация кадров → кодирование. GUI — «проект + вьюпорт»: открыть видео, выбрать стадии, обработать,
  сравнить, сохранить результат и при необходимости покопаться в промежуточных пассах.
- **Для кого.** Два типа пользователей:
  1. *Оператор* — хочет получить результат: открыть → обработать → сравнить → сохранить. Терминов пайплайна не знает и
     знать не должен.
  2. *Инженер/энтузиаст* — настраивает стадии, смотрит пассы (глубина, векторы), сравнивает бэкенды, читает лог.
  Интерфейс должен вести оператора по короткому пути, не пряча возможности инженера дальше одного клика.
- **Ключевой сценарий.** «Открыть видео → Обработать → увидеть до/после → сохранить». Всё остальное — ветки от него.
- **Ограничения.** Длинные операции (минуты на клип): нужны прогресс, оценка времени, отмена и уведомление о завершении.
  Пассы большие (десятки ГБ): нужна видимая информация о месте на диске. Работает на GPU NVIDIA; без DLL/GPU стадии
  деградируют — пользователь должен видеть, что именно деградировало.

## Принципы

1. **Один главный путь.** На каждом экране одно основное действие (кнопка «Обработать» / «Сравнить» / «Сохранить»), выделенное
   визуально; продвинутые действия — рядом, но вторичны.
2. **Говорим по-русски, не по-пайплайновому.** В основном UI — «Глубина», «Векторы движения», «Апскейл ×2», «Улучшение (NR)»,
   «Генерация кадров»; технические имена пассов (`mv_dlss`, `color_sr`) — в подсказках и в инженерном режиме.
3. **Параметры — формы, не JSON.** Выпадающие списки бэкендов, слайдеры интенсивности, переключатели масштаба; валидация до
   запуска; JSON остаётся как «расширенный» редактор.
4. **Зависимости стадий видны.** Если стадия запускается без своих guides (NR без глубины/векторов), интерфейс говорит об этом
   до запуска, а не пишет предупреждение в лог.
5. **Состояние всегда объяснено.** Пустой вьюпорт — подсказка «Откройте видео или перетащите файл»; чёрная ячейка —
   «загрузка…» или «нет кадра»; статус пасса — честный («готов, 240 кадров», а не «частично: 240 из 479»).
6. **Долгие операции.** Прогресс с процентами и оценкой времени, кнопка отмены, уведомление по завершении и переход к
   результату (вьюпорт переключается на новый пасс/результат).
7. **Время, а не индекс.** Таймлайн в секундах/таймкоде; источники с разной частотой кадров (24 и 48 fps) сопоставляются по
   времени, а не по общему номеру кадра.
8. **Сравнение — одно действие.** «До/после» по одной кнопке (шторка source↔result), пресеты сравнений (SR vs NR, source vs
   depth), а не сборка стека слоёв вручную.
9. **Раскладка живёт между запусками.** Размер окна, ширина доков, последние файлы и папки сохраняются (QSettings); закрытую
   панель можно вернуть из меню «Вид».
10. **Клавиатура и DPI.** Все действия достижимы с клавиатуры, хоткеи показаны в меню и подсказках; интерфейс читается на
    4K/ультрашироких мониторах при 100–200 % масштабирования.
11. **Ничего не теряем молча.** Несохранённый проект — вопрос при закрытии; ошибки задач — понятное сообщение с действием
    («не найдена nvngx_dlssnr.dll — положите в bin\nvidia»), а не код возврата.

## Чек-лист ревью изменения интерфейса

- [ ] Понятно ли новому пользователю, что делать дальше, без документации? (пустые состояния, подсказки, основное действие)
- [ ] Тексты — на языке пользователя, без внутренних имён пассов и JSON-ключей в основном пути.
- [ ] Каждый параметр имеет тип, диапазон и подсказку; невалидное значение нельзя запустить.
- [ ] Длинная операция: прогресс, ETA, отмена, уведомление, переход к результату.
- [ ] Ошибка: что случилось, почему, что сделать; лог — только для подробностей.
- [ ] Состояния «пусто / загрузка / нет данных / ошибка» отличимы визуально.
- [ ] Таймлайн и источники согласованы по времени при разных fps.
- [ ] Хоткеи есть в меню и в подсказках; фокус и Tab-порядок логичны.
- [ ] Раскладка и последние файлы сохраняются; панели восстанавливаются из «Вид».
- [ ] Проверено при 100 % и 150 % масштабирования, на 1080p и 4K; тёмная тема Windows.
- [ ] Новые элементы берут размеры и цвета из `app/Theme` (роли через `SetRole`), а не из встроенных `setStyleSheet`.
- [ ] Есть тест в `tests/app/` на новую логику модели/панели (Qt Test, offscreen).
- [ ] Скриншоты «до/после» приложены к MR.

Применение: этап 9 (TASK-0012, `docs/plans/09-ui-ux.md`, MR !19–!24) — чек-лист пройден по каждому MR; принципы 1–11
закрыты: 1, 3, 4 — экран проекта (MR D); 2, 8 — сравнение и чипы (MR C); 5, 7 — временная ось и плашки (MR B);
6 — страница обработки (MR F); 9, 11 — старт, раскладка, сохранность (MR E); 10 — хоткеи режимов, сравнения и
обработки в меню и подсказках (подсказки `1…9` у чипов — бэклог), проверено на 3440×1440 при 100 %; 150 % и 4K —
не проверялись на этом этапе.
