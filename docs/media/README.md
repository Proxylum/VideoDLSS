# README media: where the clips come from and how the GIFs are made

Every GIF and still in this folder is produced by `scripts/readme_media.py` from short 480p cuts of films and recordings
that are in the public domain or under a Creative Commons licence. Nothing here is from a commercial film, game or
internet meme whose owner has not allowed reuse: a public repository cannot carry those.

## Sources

| Clip | Source | Authors | Licence | Cut |
|---|---|---|---|---|

| `stk_*` | [SuperTuxKart 2.x Grand Prix, gameplay recording](https://commons.wikimedia.org/wiki/File:SuperTuxKart_2.x_GP_with_24%25_handicap_and_road_tracks_(open_source_Mario_Kart-like_Linux_game).webm), 480p transcode | SuperTuxKart team (game assets CC BY-SA 3.0 / GPL); the recording by its Commons uploader | CC BY 3.0 | see `scripts/readme_media.py` |

The 480p transcodes are the inputs as they are: typical web-video quality (VP9, ~1 Mbit/s) with its compression
artefacts. They are re-wrapped to H.264 at CRF 12 (no visible loss) so the pipeline reads them with NVDEC.

## Files

| File | What it shows |
|---|---|
| `willie_before_after.gif`, `popeye_before_after.gif`, `chaplin_before_after.gif`, `stk_before_after.gif` (stills: `willie_before_after.png`, `popeye_before_after.png`, `chaplin_before_after.png`, `stk_before_after.png`) | one region at 1:1 of the result: left — the 480p input scaled ×2 with bicubic (what a player shows), right — DLSS Super Resolution ×2 followed by Neural Rendering |
| `stk_passes_grid.gif` | the viewport's 2×2 grid at the source resolution: source, depth (`depth_dlss`, Depth Anything 3, viridis), forward flow (`mv_raw`, HSV: hue = direction, saturation = magnitude), the result after SR + NR |
| `stk_depth.gif` | source next to the depth pass (`depth_dlss`, viridis) |
| `stk_mv.gif` | source next to the motion-vector pass (`mv_dlss`, drawn as arrows) |
| `chaplin_nr.gif` | the same region of the Chaplin clip after DLSS SR (`color_sr`) and after Neural Rendering (`color_nr`): film grain, skin and fabric show the stage better than the clean game render |
| `stk_fg.gif` | consecutive frames of `color_fg` at a quarter of the speed: every other frame is generated by DLSS Frame Generation (orange border) |

Pipeline per clip (`dlssvid process -i in_480p.mp4 -o after.mp4 --scale 2`): depth (DA3) → motion vectors (Optical Flow
Accelerator) → DLSS SR ×2 → DLSS Neural Rendering → DLSS Frame Generation ×2 → H.264 encode. GIFs are 12 fps (the FG one
6 fps), palette per file (`palettegen` / `paletteuse` with Bayer dithering), which is why they show banding the MP4 results
do not have. The frames and the full-size results stay in the work folder (`Output/results/readme-media/` in the agent's
workspace, else `build/release/readme-media/`); only the GIFs and stills are committed.

## More sources to pick from

`scripts/readme_media.py --catalogue` downloads a pool of about forty more open sources of the same genres (silent-era
comedies and cartoons in the public domain, the Blender open movies, recordings of open-source games, a few CC-licensed
internet memes; `CANDIDATES` in the script) into `tests/data/cache/` and writes `<work>/sources/README.md` with a contact
sheet per file (thumbnails with time stamps) for picking scenes by hand. To use one, add its cut to `SOURCES` (`start`,
`seconds`, `crop`) and run the script for that key.

## Regenerating

```bat
models\export\.venv\Scripts\python scripts\readme_media.py            :: all clips: fetch (sha256 noted), cut, process, render, encode
models\export\.venv\Scripts\python scripts\readme_media.py --only willie --stage gif
```

Needs the built CLI (`build\release\bin\dlssvid.exe` or `DLSSVID_CLI`), ffmpeg on `PATH`, Pillow and numpy, an RTX GPU with
the DLSS DLLs in `bin\nvidia` and the depth/flow models (downloaded on first use). The unit test `[hygiene]` checks that
every image the README embeds exists, is at most 4 MB (30 MB together) and is listed in this file.
