# app — Qt 6 shell (stage 4)

`dlssvid-gui`: Qt 6.8 Widgets around the viewport. Everything here is UI only — the state model
(`core/viewport/ViewportState`), the frame cache (`core/viewport/FrameStore`), the D3D12 composite
(`core/viewport/ViewportRenderer` + `core/viewport/shaders/*.hlsl`) and the project file
(`core/viewport/Project`) live in `core/` and are shared with the CLI (`dlssvid render`,
`dlssvid project`).

| File | Role |
|---|---|
| `AppModel` | project + viewport state + FrameStore + playback paced by `PlaybackClock` (the exact rational rate, every frame shown); the panels only talk to it |
| `ViewportWindow` | `QWindow` with its own DXGI swapchain on the pipeline's device: zoom/pan, wipe drag, probe, cell click |
| `TimelineWidget` | scrubber, frame number, play/pause, ±1 |
| `ProjectPanel` | source, passes with status, stages with enable/params and «Запустить» (CLI via `TaskQueue`); «Обработать → result» saves the project and runs `dlssvid process --project` (stage 8); the `nr` stage adds «Пропатчить DLL…» — picks your `nvngx_dlssnr.dll` (and the patcher / CUDA 13.3 folders when `DLSSNR_PATCHER_ROOT` / `CUDA_PATH_V13_3` are unset) and queues `dlssvid nr-patch` (stage 6) |
| `PresetMenu`, `PresetButton` | PR-9: one menu of presets per target — the NR card's «Пресет ▾» (`StageCard`, only for `StageSchema::cardPresets`) and «Пресет обработки ▾» in the «Стадии» header of `ProjectPanel`: the presets with the difference each would make, the matching one checked, the «Перед …» slots, save / import / export / delete, the one new-projects mark, «Не прочитаны»; built on every `aboutToShow`. `PresetButton` opens it with Space / Enter / Alt+↓ (the window's Space is playback) |
| `PresetStore`, `PresetDialogs` | PR-9: the folder `AppDataLocation/presets` over `core/stages/PresetLibrary`, the Russian texts of a preset's problems and of «Не войдут в пресет», import / export / delete, the mark `presets/newProject`; `PresetSaveDialog` and the dialogs as functions the tests replace |
| `ParamText` | PR-9: values and changes in the GUI's words — `CardValueLabel` (as the card's fields), `FileValueLabel` (as a file has it), the encoder's labels, the change lines of the menus and messages |
| `SceneCutsView` | the list of the card «Склейки» (PR-13), set into it by `StageCard::setExtra`: «Найдено N склеек», up to eight chips with the cut's time (`AppModel::seekToSourceFrame` on the source's rate; Alt — the frame before it; the rest in «ещё N…»), «Почти склейки» with their score, what a new threshold changes for the stages below; read only, hidden while the stage is off or the list is not analysed yet |
| `PreviewRunner`, `NrPreviewBar` | PR-10: the NR preview of the card «Улучшение» - a frame (без истории / с историей) or a segment of 1-10 s at the cursor, made by `dlssvid nr` in the `TaskQueue`'s Preview lane into `<passes>/.preview/nr/<key>` (`core/pipeline/NrPreview`: gate over `AppModel::previewPlan`, key, check, publication, cache, GC) and shown as `color_nr@preview` on the «after» side; a cached preview shows at once, a newer request of a frame waits for the running one, a segment is killed; processing preempts it, another project or passes root drops it; «Посчитать этапы до улучшения» runs `process --stages … --no-encode`; «обновлять при изменении» after 600 ms (not while a mouse button is held); «Сохранить кадр…», «Убрать», «До: Текущее улучшение / Апскейл», the cache's line in «Версии пассов на диске»; P and «Вид → Превью кадра улучшения». `SplitButton` (`PresetMenu.h`): a default action with a menu, Space / Enter run it, Alt+↓ opens the menu; `ClaimButtonKeys` keeps Space with a button |
| `ControlMaskRow`, `ControlMaskText` | PR-8: the row «Маска управления» of the NR card after «Структура кожи» (`StageSchema::passRows`): the state on two lines (Активна · RGB · W×H / the file; Не читается / why), «Загрузить…» / «Заменить…», «Показать», «Убрать» (into the history; a folder without a loadable manifest is deleted); the import runs on `AppModel`'s one-thread `QThreadPool` (`importControlMask` → `controlMaskFinished`, `controlMaskChanged`), the viewport lets go of `mask_control` first; while it runs or a task does, the row, «Обработать», the passes folder and «Вернуть» / «Удалить» / gc of the versions panel wait. `ControlMaskText`: the Russian texts of the import's refusals and of why a folder is no mask |
| `ProjectTasks` | TASK-0067: the project each Main task of the queue was queued for; what a task's end does to the model (the «пересчитать» marks, the run time, «До \| После») applies only while that project is still open; the sources are read again also when the open project uses the task's passes folder. TASK-0070: from a task's `encode` progress on, the file the task writes is let go wherever the viewer shows it - the open project's result, or its source when the project was opened from an earlier result; no proxy build reads it, also one left from a project open before (`AppModel::releaseResult`: Windows renames nothing over an open file) and back when that task ends; a task cancelled or crashed (`TaskQueue::endedAbnormally`) while it encoded, or killed by the window closing (`TaskQueue::stopAll` waits for its end), leaves no `.dlssvid-part` file; meanwhile the result line says «заменяется новым» |
| `InspectorPanel` | layer stack and display settings, wipe, grid cell sources, pixel probe |
| `TaskQueue` | sequential `dlssvid <stage>` processes with progress parsed from `stage: N/M frames`; stage 9: a plan per task (reused stages, estimates), the measured rate of the running stage, ETA, cancel (kill; queued tasks are dropped), «не запускается» for a program that fails to start; `process: <stage> failed — …` (FG in its own process failed, the run went on) keeps that stage «ошибка» while the task succeeds (TASK-0038); PR-10: two lanes on the one process - Main (`task*` signals) and Preview (`preview*` signals, one shared row): a Main task preempts the previews (`previewPreempted`, the running one killed), a preview is refused while a Main task runs or waits; `busy()` = either lane runs, `mainBusy()` / `previewBusy()` |
| `ProcessingPanel` | the processing page (stage 9): elapsed / left, overall and per-stage progress, «Отменить», «Свернуть в фон», log tail, «Показать результат» / «К проекту»; a stage that failed in a finished run, or one the runner skipped as unavailable (TASK-0071: «пропущена», its reason in the tooltip and the note): «Готово за … · без стадии «…»» and the page stays with «Показать результат»; an upscale that fell back to NIS: «готово запасным способом» |
| `StageAvailability` | TASK-0071: the line «можно ли запустить здесь» of the NR and FG cards — what is known without NGX (the GPU, the driver ≥ 616.56 for NR, the DLLs) or the last «Проверить» (`AppModel::checkStage`: `dlssvid nr|fg --check` with the project's settings in a process of its own) |
| `ResultBar` | the result line (TASK-0013): what the result video is and «Сохранить как…» / «Открыть папку» / «Экспорт пассов…» / «Другое видео» |
| `Theme` | the look after the mockups (TASK-0017): Fusion + dark palette + one stylesheet; widgets pick variants through the `role` property (`SetRole`) |
| `LogPanel` | spdlog sink |
| `StartPage`, `RecentPreviews` | the start screen after the mockup «1 · Стартовый экран»: two centred columns — the drop zone, «Открыть видео…» / «Открыть проект…», the readiness card with a status dot; the recents on the right as cards with a 96×40 preview frame (decoded on a worker thread, PNG-cached by path, size and mtime), «face — результат готов» / «глубина и NR посчитаны» and «1920×800 24 fps → 3840×1600 48 fps · вчера»; the footer lives in the status bar |
| `MainWindow` | docks, menus, hotkeys (1..9 sources, F fit, Ctrl+0 1:1, W wipe, Space play, ,/. step), PNG screenshot with cell labels; stage 9: start page / work area / processing page, QSettings, recents, «До | После» after a run, tray notification when the window is minimised or in the background |

Build: `-DDLSSVID_BUILD_APP=ON` (default) with `QT_ROOT` pointing at `.../Qt/6.8.x/msvc2022_64`;
without Qt the GUI is skipped with a warning. `windeployqt` runs post-build, so the executable
starts from the build tree. Tests: `tests/app/` (offscreen platform).
