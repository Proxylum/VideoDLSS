# Изменения

Формат версий — semver; версия задаётся в `CMakeLists.txt` (`project(dlss-video VERSION …)`), пакет —
`dlss-video-<версия>-win64.zip` (`docs/release.md`). Версия релиза **не** входит в отпечатки пассов: за них отвечает версия
алгоритма пассов (`kPassToolVersion`, `core/pipeline/PassFingerprint.h`), которую поднимают только когда результат стадии
меняется при тех же параметрах.

## 0.3.0 — 2026-09-25

Открытые нейросетевые апскейлеры рядом с DLSS SR, стартовый экран и карточки стадий по макетам, воспроизведение без
мерцания, битрейт по умолчанию; README для публикации на GitHub (сборка, установка, модели, рантаймы NVIDIA), `sr_worker/`
в пакете.

- Кодирование: битрейт по умолчанию подбирается по разрешению, частоте и кодеку результата (`core/io/EncodeDefaults`:
  H.264 1080p30 ≈ 16, 4K30 ≈ 45, 4K60 ≈ 70 Мбит/с; HEVC ≈ 0,65×, AV1 ≈ 0,55×) и в CLI, и в GUI — раньше без `b` NVENC
  кодировал 3840×1600 при ~1,4 Мбит/с. Карточка «Кодирование»: «Авто» с показом выбранного значения, пресеты 20 / 35 /
  50 / 80 / 120 / 200 Мбит/с, «Свой…» в Мбит/с, оценка размера файла; для FFV1 битрейта нет («без потерь»).
  В CLI явное значение — `--codec-opt b=50M`, лог сообщает выбранный автоматически.
- Оформление GUI по макетам (`app/Theme`): тёмная палитра и таблица стилей с размерами и отступами из макетов —
  кнопки 36 px (главное действие в акценте 48 px), табличные 24 px, сегменты 32 px, чипы 30 px, поля 30 px,
  карточки 9×14 px, панели 48 px; переключатель «Инженерный режим» — флажок. Колесо мыши над невыделенным списком,
  счётчиком или слайдером прокручивает страницу, а не меняет значение (раньше прокрутка панели проекта могла
  переключить бэкенд стадии).
- Таймлайн: кнопки воспроизведения нарисованы в цвете текста темы (стандартные иконки Fusion терялись на тёмной
  панели); кнопка-переключатель зацикливания (`L`, пункт в меню «Вид», запоминается в QSettings) — по концу
  ролика воспроизведение начинается сначала.
- Вьюпорт: пока точный кадр источника ещё грузится, на экране остаётся ближайший загруженный кадр этого источника
  (`FrameStore::TexturesAt`), а не плашка «загрузка…» — исправлено мерцание сплит-скрина «До | После» при
  воспроизведении (результат 3840×1600 при 48 fps декодируется на CPU медленнее реального времени, и на каждом
  отстающем тике ячейка уходила в серую плашку или в чёрный). Подпись ячейки и пробник честно пишут «загрузка…»,
  пока показан предыдущий кадр; кадра нет — по-прежнему штриховка. Воспроизведение показывает каждый кадр: тик ждёт,
  пока у всех показанных источников загрузится следующий кадр (медленный декод играет медленнее реального времени,
  а не пропускает кадры); кадр, не пришедший за 2 с, пропускается.
- Стартовый экран — по макету «1 · Стартовый экран»: две колонки по центру (560 и 440 px), слева заголовок,
  зона перетаскивания со стрелкой, кнопки и карточка готовности с цветной точкой (зелёная — все DLL на месте, жёлтая —
  чего-то нет, красная — WARP), справа «Недавние» карточками: превью 96×40 (первый нечёрный кадр результата или
  исходника, `app/RecentPreviews`: FFmpeg на CPU в рабочем потоке, PNG-кэш в каталоге кэша приложения по пути, размеру
  и дате файлов), «face — результат готов» / «static — глубина и NR посчитаны», строка «1920×800 24 fps → 3840×1600
  48 fps · вчера 14:02» или «… · 2 из 5 стадий · сегодня», третьей строкой — путь к файлу (сокращается в середине,
  имя файла видно; подсказка при наведении — название, путь и состояние); щелчок открывает файл. Подвал «Готов · Пассы по умолчанию:
  рядом с видео» — в строке состояния окна. Строка готовности при полном комплекте DLL: «RTX 4070 Ti SUPER · драйвер
  616.92 · DLSS SR, Neural Rendering и генерация кадров доступны».
- Апскейл: бэкенд-заглушка `rtxvsr` (RTX VSR без SDK) удалён из фабрики, схемы параметров и CLI — в списке «Метод»
  остались DLSS SR, NIS и бикубик; у `dlssvid upscale` `--backend` по умолчанию теперь `dlss` (стояло `rtxvsr`, и
  команда без `--backend` всегда уходила в запасной NIS). Открытые альтернативы DLSS SR — предложение в
  `docs/plans/05-upscale.md`.
- Апскейл: бэкенд `trt` — открытые нейросети через TensorRT: Real-ESRGAN x2plus (по умолчанию, качество), компактная
  realesr-general-x4v3 (быстро) и x4plus; веса с GitHub-релизов Real-ESRGAN (BSD-3) по sha256, ONNX экспортируется при
  первом запуске (`models/export/export_realesrgan.py`), один engine на размер тайла; тайлы с 16 px контекста, родной
  масштаб модели пересемплируется к цели (×1.5, ×3). В карточке стадии — метод «Нейросеть (TensorRT)» и выбор модели;
  в CLI `--backend trt --model … --tile … --models-dir …`. Параметры модели привязаны к бэкенду: отпечатки пассов
  DLSS/NIS не изменились.
- Апскейл: бэкенд `worker` — RealBasicVSR через PyTorch-воркер `sr_worker/` (видео-SR с распространением по кадрам:
  окна по 15 кадров с перекрытием 3, временная стабильность, которой нет у покадровых моделей); сеть на чистом PyTorch
  без mmcv, официальный чекпоинт с зеркала HF по sha256 (Apache-2.0), воркер сам приводит ×4 к размеру цели. В карточке
  стадии — метод «RealBasicVSR (PyTorch)»; в CLI `--backend worker --window … --overlap …`. Стадия апскейла умеет
  окна кадров для CPU-бэкендов.
- Публикация: лицензия MIT (`LICENSE`, в пакете рядом с README и CHANGELOG); в документации нет внутренних хостов и путей
  машины разработки (плейсхолдеры `https://<хост GitLab>`, `<SDK>`); тест гигиены репозитория
  `tests/unit/test_repo_hygiene.cpp` следит за этим.

## 0.2.0 — 2026-09-22

Этап 9 (UI/UX) и хвосты после него: GUI ведёт оператора по одному пути «Открыть видео → Обработать → До | После →
Сохранить», пассы переиспользуются по отпечатку и хранят версии.

### Интерфейс (`dlssvid-gui`)
- Стартовый экран: перетаскивание видео, «Открыть видео…» / «Открыть проект…», готовность GPU / драйвера / DLL DLSS,
  недавние файлы с состоянием проекта.
- Экран проекта: источник (кадр, звук, папка пассов с кнопкой «изменить…», хэш), «Что получится» (размер и частота
  результата, время с учётом переиспользования, свободное место на диске), карточки стадий с формами по схеме параметров
  и состояниями плана («переиспользуется», «пересчёт: почему», «будет посчитано»), предупреждение о запуске NR / FG без
  глубины и векторов, чипы версий пассов, панель версий на диске («Сравнить», «Вернуть», «Удалить», «Очистить старые»),
  одна кнопка «Обработать · N стадий» (`Ctrl+Enter`), карточка кодирования (кодер хранится в проекте).
- Страница обработки: «Прошло / Осталось» (оценки плана, затем измеренный темп стадии), прогресс по стадиям
  (переиспользованные засчитаны сразу), «Отменить» (готовые стадии остаются на диске и переиспользуются), «Свернуть в
  фон», хвост лога, «Показать полный лог»; по завершении — автопереход в «До | После», уведомление в трее, если окно
  свёрнуто; после отмены или ошибки — объяснение и «К проекту».
- Результат: строка «Результат · 3840×1600 · 48 fps · 479 кадров · со звуком · обновлён … · готов за …» с действиями
  «Сохранить как…», «Открыть папку», «Экспорт пассов…» (EXR-последовательности задачами `dlssvid export`), «Другое видео»
  (= «Файл → Закрыть проект», `Ctrl+W`).
- Сравнение одним действием: панель «До | После» (шторка исходник ↔ результат, `W`) / «Только после» / «Сетка 2×2», чипы
  источников с человеческими именами («Исходник», «Глубина», «Векторы», «Апскейл», «Улучшение», «Генерация», «Результат»)
  и меню предыдущих версий пасса, пресеты в меню «Вид», клавиши `1…9` по порядку чипов, «Инженерный режим» (`Ctrl+E`) —
  стек слоёв, инспектор, JSON параметров, лог.
- Таймлайн по времени: источники 24 и 48 fps сопоставляются по времени, таймкод, переключатель частоты, плашки
  «загрузка…» / «нет кадра» вместо чёрных ячеек, подписи ячеек с размером источника, кадром и состоянием.
- Раскладка и сохранность: геометрия окна, доки и папки диалогов в QSettings, панели возвращаются из меню «Вид»,
  «Недавние», drag-and-drop на окно, «*» в заголовке и сохранение проекта рядом с видео при закрытии, вопрос при закрытии
  во время обработки.

### Пайплайн и CLI
- Отпечаток пасса (sha256 канонического JSON: хэш исходника, стадия, параметры с умолчаниями схемы, отпечатки входов,
  инструмент — бэкенд, модель, DLL NVIDIA) в `manifest.json`; пасс переиспользуется только при совпадении отпечатка,
  смена параметра пересчитывает стадии ниже по цепочке. Пассы без отпечатка (0.1.0) усыновляются как `legacy`.
- Версии пассов: текущая — `<passes>/<pass>/`, предыдущие — `<passes>/<pass>.v/<YYYYMMDD-HHMMSS_fp8>/`; хранятся две
  последние (`pass_versions_keep` в проекте), сборщик не удаляет версии, на которые ссылаются входы других версий.
- `dlssvid process --plan` (решения reuse / run / restore с причинами), `--keep-versions`, `--force stage,…`; `dlssvid
  passes list|use|gc`; параметры стадий проверяются по схеме (`core/stages/ParamSchema`) в CLI и GUI; кодер и опции
  кодирования — из файла проекта; оценки времени и диска прогона (`core/pipeline/Estimates`); `dlssvid render --time`.
- Файл проекта: `viewport.time` в секундах вместо `frame` (старые проекты читаются как `time = frame / fps`), поля
  `pass_versions_keep`, `encode`, `source_hash` (кэш хэша исходника по размеру и mtime).

### Исправления
- `FrameStore`: зависание при остановке (потерянное пробуждение загрузчика) — стресс-тест.
- Векторы движения внутри `process` снова декодируют видео через NVDEC после стадии глубины: FFmpeg отказывал в NVDEC
  из-за флагов первичного CUDA-контекста; декодер выравнивает их (`cudaSetDeviceFlags`).
- Открытие видео только ради информации о потоке логируется на уровне debug (одна строка «open» на чтение).
- Тесты: QSettings тестов — INI-файл на процесс; тесты запускаются из папки вне клона (обновлятор NGX
  `nvngx_update.exe` наследовал рабочую папку и ронял `git clean` в CI).
- Кэш TensorRT-движков пишется и читается по путям длиннее 260 символов (`Win32LongPath`, префикс `\\?\`): пакет,
  распакованный в глубокую папку, собирал движок несколько минут и не мог его сохранить.

Тесты: 217 (юнит, интеграционные, приложение, golden). Golden-эталоны не менялись.

## 0.1.0 — 2026-09-20

Первый пакет: этапы 0–8. Пассы и конвенции (EXR / PNG / TIFF / NPZ / raw, `manifest.json`, экспорт / импорт /
конвертация), глубина (DA3 metric и Metric-VDA через TensorRT, Python-воркер), векторы движения (NVIDIA Optical Flow,
SEA-RAFT), вьюпорт на D3D12 (`dlssvid-gui`, `dlssvid render`), апскейл (DLSS SR по умолчанию, NIS, бикубик; RTX VSR
опционально), DLSS 5 Neural Rendering (NGX Feature 18 через форвардер, `dlssvid nr-patch`), генерация кадров (DLSS-G через
NGX, RIFE 4.9, смешивание), `dlssvid process` над кэшем пассов с копией аудио, `dlssvid bench`, golden-тесты (в том числе
на установленной копии), пакет CPack (обычный и `full` с TensorRT, cudart и ONNX-моделями), CI на собственном раннере с
RTX.
